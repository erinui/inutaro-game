# サイトの更新と操作の信頼性 SDD実施仕様

作成日・最終更新: 2026-10-11 / 状態: 実装・TDD・統合検証済み、公開確認中

最新情報更新の障害分離、ゲーム説明のキーボード操作、SPメニューのフォーカス復帰、TOPカード画像の代替表示を定義する。[改修計画](site-reliability-plan.md)が実施順とフェーズの正本、本資料が設計・受け入れ条件の正本となる。

## 1. 前提と変更境界

- 本番は `https://erinui.com/`、Cloudflare Workersの静的アセット配信。APIサーバーの新設はしない。
- 基準HEADは `ecf9af55da6af3bea347648d01c09fb5b3817d74`。実装開始時に現在HEADと自動更新差分を再確認する。
- [SEO・読み込みSDD](seo-performance-sdd.md)のAは公開済み。既存metadata、構造化データ、静的JSON優先、no-cache、lazy/asyncを保持する。B・Cの圧縮候補は保留のまま。
- 通常表示の原稿、デザイン、リンク、アンカー、カードの並び・枚数・寸法、マップの動き、看板の重ね合わせ・10秒切り替えを維持する。画像失敗時のmedia枠だけは本資料で指定した代替表示を許可する。
- 「動きを減らす」への対応は利用者指示で対象外。`prefers-reduced-motion`、装飾アニメーション、smooth scroll、タイマーの変更を混ぜない。
- ページ追加、外部アカウント操作、DNS・検索管理、取得周期変更、LINE自動取得、秘密の追加公開、既存未追跡素材の変更は対象外。

| 仕様ID | 対象 | 許可する変更 |
| --- | --- | --- |
| REL-DATA-01 | 更新workflow・生成処理 | 取得先別の作業出力、成否分離、検証・反映、成否レポート、競合防止 |
| REL-GAME-01 | あそびかたダイアログ | フォーカス循環、背面操作防止、閉じ方ごとの復帰、表示中の入力隔離 |
| REL-NAV-01 | 共通ヘッダー | 開いているSPメニュー内からのEscapeに対するフォーカス復帰 |
| REL-IMAGE-01 | TOPのコンテンツカード | img error時の既存代替表示、早期・遅延エラーの捕捉 |

## 2. 最新情報の生成と障害分離

### 2.1 実行方式

現行workflow `.github/workflows/update-youtube-latest.yml` のschedule `10 */4 * * *` とworkflow_dispatchを保持する。cronはUTCであり、日本時間は01:10/05:10/09:10/13:10/17:10/21:10。GitHubによる起動遅延は、取得処理の失敗と区別する。

統合入口 `scripts/update-home-latest.mjs` を新設し、既存3スクリプトを取得先別の一時出力先で順に実行する。並列ジョブから別々にmainへpushする方式は採用しない。取得形式、最大6件、JSONキー、サムネの命名、noteの黒帯処理は現行維持。LINEの静的JSONを更新対象へ含めない。

既存スクリプトには `HOME_LATEST_OUTPUT_DIR` で出力先を指定できる小さな変更を加える。指定がない単体実行の既定パスは維持するが、定期更新・通常の手動更新は統合入口に一本化する。単体スクリプトの直接実行を、統合入口と同じ障害保護がある運用として説明しない。

一時出力と結果レポートは公開assets外に置く。workflowは固定concurrency group、`cancel-in-progress: false`、job timeout 15分を指定する。取得の停止上限は各HTTP要求12秒、取得先の子プロセス全体180秒。自動リトライは新設せず、時間切れも失敗として捕捉する。noteの既存12秒要求上限は維持する。

### 2.2 状態と処理順

1. 実行開始時のmain、対象ファイル一覧・SHA、取得先設定を記録する。APIキー・トークンは記録しない。
2. 各取得先を `success` / `failed` / `skipped` に分類する。失敗しても次の取得先へ進む。SUZURIのsecret未設定は現行どおりskipped、YouTubeキー未設定はfailedとする。
3. 取得先の終了コードだけでなく、出力JSONと必要な画像の整合性を確認する。終了0でも不正な出力はfailedとする。
4. 全取得処理後、検証済みsuccessのファイル群だけを本番用assetsへ反映する。failed/skippedの既存JSON・画像・fetchedAtを変更しない。
5. successの対象内でのみ、旧サムネの削除を反映する。対象外ファイルや失敗した取得先の旧画像を削除しない。
6. 反映中の書き込み失敗では、退避した変更前バイト列から反映全体を復元し、コミットへ進まない。通常ディレクトリ上の複数ファイルrenameを「同時に原子的」とみなさない。
7. workflowは許可された出力パスだけをstageし、差分があれば1コミット・1pushする。JSONが同一でも新規画像・削除を含む差分を判定する。`git add -A -- assets/home-city` で無関係な素材を一括stageしない。
8. 保存・pushが成功した後に取得結果を集計する。いずれかfailedなら最終ステップを失敗にし、Job Summaryに取得先ごとの結果と、正常分の反映状況を残す。すべてsuccess/skippedなら成功とする。

統合入口は、取得先の部分失敗を結果レポートに残しつつ、正常分の反映が完了すればworkflowの保存ステップへ進める終了コードを返す。レポート欠落、統合処理の例外、反映・復元失敗は致命的失敗としてコミットを止める。最終判定を保存前へ置いたり、continue-on-errorだけで部分ファイルを公開したりしない。

### 2.3 出力検証と許可パス

| 取得先 | 反映可能なファイル | 合格条件 |
| --- | --- | --- |
| YouTube | `youtube-latest.json`、`youtube-thumb-1..5.jpg` | ok=true、channelとvideosの現行構造、0〜6件。thumbnail URLのある先頭5件の対応画像が完全に保存されている |
| note | `note-latest.json`、`note-thumb-1..6.(png/jpg/webp)` | ok=true、itemsが0〜6件。thumbnailUrlがある項目は対応するローカル画像が存在し、そのパスが許可範囲内 |
| SUZURI | `suzuri-latest.json` | ok=true、itemsが0〜6件、現行の商品URL・画像・価格の型を満たす。画像は従来の外部URL |

ファイル名の検査、JSONの型、必須のタイトル・URL、ローカル参照の存在、画像ファイルの非空・拡張子と形式署名の整合を検査する。これは完全なデコード可否の保証ではなく、ブラウザでの読込失敗はREL-IMAGE-01で別途処理する。空配列は正常取得と通信失敗を区別して許可する。現行ブラウザの空データ時の初期カード保持を変更しない。任意パス、`..`、シンボリックリンク、未許可ファイルを反映しない。

応答検査も行う。YouTubeのitems、SUZURIのproductsは配列を必須とし、noteは既存のタグ抽出処理でrss/channelを確認する。200応答でも構造が欠ける場合は取得失敗であり、0件の正常フィードへ変換しない。新しいパーサーや外部依存は導入しない。

YouTubeの必要サムネ取得失敗は取得先全体をfailedにし、JSONだけ新しくしない。noteの個別記事OGP失敗は既存どおり、その記事のthumbnailUrlを省いた正常データとする。画像変換環境不在の元画像保存も維持する。以前のnote画像を無条件に復元しない。

### 2.4 競合と公開

更新処理同士は直列化する。ただし別の開発pushまで排他にできるわけではない。push時の競合は通常の失敗として報告し、force pushや自動的な変更破棄は行わない。新しいmainから再実行する。

一部取得失敗でも正常分がpushされた場合、本番へ正常分が反映され得る。workflowの最終失敗と「全件が未公開」は同義ではない。レポートには更新済み/前回保持/secret未設定/保存失敗を区別し、キー、Authorization、APIキー付きURL、外部応答本文を出力しない。新しい通知・監視サービスは追加しない。

## 3. ゲーム説明のフォーカス管理

既存 `#howto-panel` のrole=dialog、aria-modal、hidden、文面、寸法を維持する。設計は[W3Cのモーダルダイアログ指針](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)に沿う。

| 操作 | 期待動作 |
| --- | --- |
| あそびかたを開く | 閉じるボタンへフォーカス。`.game-shell` 内のダイアログ以外の兄弟要素をinertにし、元のinert状態を保存 |
| Tab / Shift+Tab | 表示中・有効・操作可能な内部要素を循環。現在は閉じるボタン1個なので、どちらも同じボタンへ留まる |
| 閉じるボタンのEnter / Space | ブラウザ標準のボタン操作で閉じる。ゲームのジャンプには渡さない |
| Escape / 閉じるボタン / 背景クリック | 既存どおり閉じる。保存したinertを復元してから、あそびかたボタンへフォーカスを戻す |
| ゲーム開始など内部処理から閉じる | 背面状態を復元するが、表示されなくなるあそびかたボタンへフォーカスを強制移動しない |
| すでに閉じている状態でclose処理 | 無関係なフォーカスやinertを書き換えない |

`.game-shell` 自体をinertにするとダイアログも操作できなくなるため禁止する。ゲーム説明を開く前に押下キー状態を解除し、表示中のキーをゲーム移動・ジャンプへ渡さない。Tabの処理後に `state.keys` へ追加する経路も止める。開閉後に押しっぱなし状態を持ち越さない。

現行の表示中keydownはTab以外を一括preventDefaultしているため、この境界を見直す。Tab循環・Escapeに必要な抑止だけを行い、Enter/Spaceによるボタン操作と説明文の標準スクロールは許可する。表示中は標準動作を許可したキーもゲーム側の入力経路へ進めない。

Escape等の既存復帰処理と新しいclose処理が二重に動かないよう責務をまとめる。ただしゲーム全体の入力、時間計測、描画、音声、結果画面、保存・共有は再設計しない。native dialogへのHTML構造置換や新しいモーダルライブラリは採用しない。

## 4. SPメニューのフォーカス復帰

既存のCSS、開閉アニメーション、760/761px境界、リンクの順序と現在ページ除外を維持する。SPメニューは非モーダルのナビゲーションであり、ゲーム説明のようなTab閉じ込め・背面inertは追加しない。

Escape処理はSP、メニューが開いている、操作対象がメニュー内またはtoggle、の条件をすべて満たす場合に限る。その場合のみ閉じてtoggleへフォーカスを戻す。閉じたメニュー、PC、別の操作対象からのEscapeには干渉しない。

toggle自身で閉じる場合は既存フォーカスを維持する。リンククリックは通常どおり閉じて遷移し、toggleへ戻す処理を差し込まない。PCへのresizeは開閉状態をリセットするが、PCで表示され続けるリンクからフォーカスを奪わない。aria-expandedとaria-labelの更新は維持する。

境界幅のTDDで、SPへ戻った直後は既存のvisibility遷移190ms中に閉じたリンクへTabが移ることを確認した。見た目のアニメーションは維持し、SP閉状態のnav自身だけをinertにする。開くと解除し、PCでは常に解除する。これは背面全体をinertにするモーダル化ではなく、閉じたnavの操作対象除外である。

## 5. カード画像の代替表示

対象はTOPの `.content-carousel-card img.content-card-media` の初期HTMLと動的生成分。キャラクター画像、マップ、YouTube看板、共通ロゴ、下層ページ、ゲーム資産は対象外とする。

| 状態 | 処理 |
| --- | --- |
| 正常画像 | 既存のsrc、class、alt、loading=lazy、decoding=async、cover/containを維持。追加取得やデコード待ちで遅延させない |
| noteカードの画像失敗 | 既存の `assets/home-city/map_blog.png` をcontain・既存note用表示で1回だけ試す |
| note代替も失敗 / その他カテゴリの失敗 | 既存 `content-card-media-placeholder` の16:9枠とカテゴリ表示へ差し替える。新しい画像や説明文は追加しない |
| 画像がない / AND MORE | 既存のplaceholderと「+」をそのまま維持。エラー用処理を適用しない |

動的画像にはsrc指定前にerror handlerを登録する。初期HTML画像はhandler登録時点ですでに `complete && naturalWidth === 0` となっている失敗も捕捉する。lazy画像は後からのerrorを処理する。登録は冪等にし、note代替の再帰的な再試行を防ぐ。初期画像が既にブログ建物イラストなら、同じURLを再試行せずplaceholderへ進む。

交換するのはmedia要素だけで、カード・トラックをreplaceChildrenしない。16:9の枠、カード高さ、幅、文章、aria-label、href、target、rel、フォーカス、スクロール位置を保持する。placeholderは既存どおりaria-hiddenとし、カテゴリを重複読み上げしない。失敗画像のaltが枠外へはみ出す表示を残さない。

| テストfixture・helper | 固定データ、承認差分、旧baselineへの逆変換を追加 |

既存 `tests/site-design.test.mjs` はhome.js、site-nav.js、ゲーム等をSHA保護し、`tests/seo.test.mjs` はゲームコードとbodyを保護している。今回の差分を無条件に許可するハッシュ上書きは行わない。

`tests/fixtures/site-reliability-changes.json` と逆変換helperを追加し、仕様ID、ファイル、変更前/後の限定コード片、適用件数を登録する。検査時は今回の差分を逆変換してから既存SEOの逆変換・旧URL復元を適用し、旧SHAへ照合する。関数全体やbody全体を除外する正規化は禁止する。

JS参照バージョンの変更もファイルごとに明示し、サイト全体のCSS・画像バージョンを一括更新しない。自動生成JSONの更新は別の入力変更としてコミットとSHAを記録し、承認コード片へ混ぜない。基準の全面再採取でテストを通さない。

## 8. 検証方法と判定
