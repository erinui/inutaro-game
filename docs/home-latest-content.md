# トップページ最新コンテンツ表示

最終更新: 2026-10-20（現行のカード・分類表示とラベル撤去の範囲を整理）

ニュースの新着順・最大12件は2026-10-18に公開確認済み（当時のCI全187件）。今回のゲーム／キャラクターのラベル18件撤去はローカル検証済み・本番未反映で、取得処理・データ件数・更新周期は変更していない。全体の公開状態は[開発まとめ](project-summary.md)、追加承認と検証は[TOP改修SDD](top-redesign-sdd.md)第20〜21節を参照する。

## 目的

トップページのYouTube、ブログ、グッズ、LINEスタンプを、各サービスの最新情報へ直接つながるカルーセルとして表示する。

## 表示ルール

- 取得上限は各ジャンル6件。
- 取得結果が6件ある場合は、先頭5件と `and more` カードを表示する。
- 取得結果が5件以下の場合は、取得できた全件のみを表示する。
- `and more` は各サービスの一覧ページへ別タブで遷移する。
- SPではカードを横スクロール、PCでは左右ボタンで操作する。
- moreカードの見出しは「まだまだあるよ」。枠付きカテゴリは混在するニュースだけに表示し、通常カテゴリ枠には設けない。
- ニュースは通常枠と別契約で、全候補の新着順・最大12件、moreカードなし。詳細は末尾のニュース仕様を参照する。
- TOPは321×432px基準・画像contain。PCも常時3枚とは限らず、固定マップを除いた残り幅で表示する。SPでも左右矢印を使え、1枚分＋間隔22pxで進む。全件収まる場合は操作ボタンを非表示にする。

## データ元と更新方式

| ジャンル | データ元 | 更新方法 | 表示ファイル |
| --- | --- | --- | --- |
| YouTube | YouTube Data API v3 | GitHub Actionsで4時間ごとの10分 | `youtube-latest.json`、schemaVersion 2のlocalThumbnailで指定した`youtube-thumb-{id}-{hash}.webp` |
| ブログ | note RSSと記事ページのOGP画像 | GitHub Actionsで4時間ごとの10分 | `note-latest.json`、`note-thumb-1..6.(png/jpg/webp)` |
| グッズ | SUZURI API v1 | `SUZURI_ACCESS_TOKEN` 登録後、GitHub Actionsで4時間ごとの10分 | `suzuri-latest.json` |
| LINEスタンプ | LINE STORE作者ページの公開情報 | 現在は静的JSONを手動更新 | `line-stamps.json` |

Actionsの指定は`10 */4 * * *`（UTC基準、JSTの01/05/09/13/17/21時10分）。起動時刻の保証ではなく遅延する場合がある。旧JPGは初期HTML原本のフォールバックとして残るが、公開ビルドは検証済みJSONから保存済みWebPを初期画像へ反映する。

## ブラウザでの読み込み

本番 `erinui.com`、ローカルlocalhost/127.0.0.1、GitHub PagesではYouTubeの静的JSONを先に読み、正常応答ならAPIへアクセスしない。その他のHTTPホストでは既存APIを先に試す。HTTP失敗・ネットワーク例外・JSON解析失敗・無効データの場合は次候補を1回試し、両方失敗時はHTMLの初期表示を保持する。

4ジャンルのJSONは `cache: no-cache` で再検証し、未変更時は保存された本文を再利用する。カード画像はsrc設定前にlazy/asyncを指定し、画面内に入るタイミングで表示する。マップの看板サムネは遅延読み込みにしない。取得件数・10秒表示切替・生成周期・URLは従来どおり。詳細と検証結果は[SEO・読み込みSDD](seo-performance-sdd.md)を参照。

## SUZURIの運用

SUZURI APIはアクセストークンを必要とする。GitHub Repository Secretとして `SUZURI_ACCESS_TOKEN` を登録する。未登録でもワークフローは失敗せず、既存の `suzuri-latest.json` とHTML内の案内カードをそのまま使う。

取得対象は商品名、商品URL、商品画像、税込価格、公開日時。トークンはブラウザ側のJavaScriptやJSONへ書き出さない。

## Noteの運用

`scripts/update-note-latest.mjs` は、note RSSから最新6記事のタイトル、概要、URL、公開日を取得する。その後、各記事ページの `og:image` を取得し、上下の黒帯をトリミングしてサイト内の `assets/home-city/note-thumb-*` として保存する。

- ブログ枠とおしらせ枠は、保存済みの見出し画像を `16:9` のカード画像として表示する。
- 画像が未設定、取得失敗、形式未対応の場合は、既存のブログ建物イラストを表示する。
- 以前の取得結果に含まれなくなったサムネイルは更新時に削除する。
- ブラウザからnoteを直接取得しないため、CORSや外部画像の一時的な表示失敗の影響を受けにくい。

## LINEスタンプの運用

LINE STOREには作者一覧を取得する安定した公開APIがないため、サイト公開中の自動スクレイピングは行わない。`line-stamps.json` に作者ページで確認した販売中作品の名称、商品URL、サムネイルURLを記録する。

新作公開時や販売終了時に、作者ページを確認してJSONを更新する。現在の登録作品は4件であるため、`and more` カードは表示しない。

## 障害時の扱い

- 取得JSONが読み込めない場合は、HTML内の案内カードを残す。
- GitHub Actionsの取得に失敗しても、直前に成功したJSONを表示し続ける。
- カード画像の読み込み失敗は既存代替表示へ切り替え、カード本文と遷移リンクを残す。

## 信頼性改修の採用仕様 2026-10-11

`scripts/update-home-latest.mjs` を通常更新の入口として採用した。取得先別に公開assets外で生成・検証し、正常分だけ反映する。失敗・secret未設定の取得先はJSON、画像、fetchedAtを維持する。保存・push後に最終成否を判定するため、一部失敗でも正常分が公開される場合がある。反映中の書き込み失敗は変更前バイト列へ復元する。許可パスだけを1コミットで保存し、push競合時はforce pushせず新しいmainから再実行する。

初期・動的・遅延カード画像の失敗を捕捉し、noteは既存建物イラストを1回だけ試し、再失敗とその他カテゴリは既存16:9 placeholderへ切り替える。カード本文・リンク・寸法・スクロール位置を保持する。4時間ごとの更新、最大6件、AND MORE、ニュース集約、看板3サムネと統計の10秒切り替え、LINEの手動管理は維持する。「動きを減らす」対応と画像・フォント圧縮は含めない。

## ニュース表示の変更（2026-10-18）

ニュースは、取得済みの動画・記事・商品・LINE作品と既存ゲームを横断し、有効な更新日（updatedAt）または公開日（publishedAt）の新しい順で最大12件を表示する。カテゴリごとの1件制限とゲーム先頭固定は廃止し、ニュースにAND MOREは設けない。12件未満の場合は実数でカルーセルを終了する。同日時は入力順、日時不明は末尾とし、取得日fetchedAtで新着に見せない。重複URLは1件だけ採用する。

これはニュースの表示候補選択だけの変更で、各サービスの取得件数上限6件、通常カテゴリ枠の5件＋more、API頻度、LINE手動管理は従来どおり。JS読み込み前/無効時の静的フォールバックも変更しない。`755bf41` / `fd53ee4` で本番公開し、新しい順の12件と末尾停止をPC/SPで確認済み。[仕様・確認結果](top-redesign-sdd.md#16-ニュースの新着順最大12件)を参照。
