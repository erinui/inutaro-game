# TOP新レイアウトのUI UX デザイン SEOレビュー

現行仕様・改修工程・受入条件は[TOP改修SDD](top-redesign-sdd.md)を参照。本書は検討・レビュー時点の記録として保持する。

レビュー日: 2026-10-18 / 対象: PC新レイアウト検討 / 状態: 改修前の所見を保存

このレビューに対するFigmaの改修・設計反映は[対応記録](top-redesign-review-fixes-20261018.md)と設計書1.4を参照。以下は改修前時点の所見。

固定マップをサイトの入口にし、右にレコメンドを集約する方向は採用を続けられる。既存素材・書体・輪郭・配色がつながり、一般的な情報サイトとは異なる個性がある。改善の優先対象は、初訪問者に対する説明、マップの操作の発見、ニュースが収まる条件の堅牢性、カルーセルから先の導線である。

大きなマップ、犬タローの吹き出し、ニュースまでの初期表示、統一カード、キャラクター紹介を画面外に置く方針は維持する。レビューを理由に案内を小さく戻したり、不要な装飾ラベルや画像アイコンを追加したりしない。

## 1. 対象と根拠

- [PCのFigma](https://www.figma.com/design/XEgScjFWiQZTUZcnbn24RO/?node-id=2449-21933)の現在表示を今回取得した。
- 今回のPC画面キャプチャ（非公開のローカル証跡: `drafts/top-redesign-review-20261018/01-pc-entry.png`）を画面上の所見の根拠とする。Figma編集画面のため、画像の下端は実ブラウザの900px境界を示さない。
- PC初期表示の寸法条件と未決事項は[詳細設計書](top-redesign-detail-spec.md)を参照した。768px・720pxの試験完了やブラウザ動作は今回の画像から断定しない。
- SEOはローカルの既存 `index.html`、`home.js`、`home.css` とGoogle公式資料を照合した。既存HTMLは新Figmaを実装したものではない。
- SPの最新画面・全カルーセル状態・キーボード・読み上げ・実機表示・公開サイトの速度・Search Consoleは今回未検証。SPに関する記述は実装確認事項として扱う。

## 2. 確認した利用手順と評価

| 手順 | 利用者の行動 | 評価と確認範囲 |
| --- | --- | --- |
| 1 | TOPを開き、サイトと入口を理解する | 世界観と操作説明は明確。誰の何があるサイトかの短い説明は不足。PC画面を確認 |
| 2 | マップで気になる場所を選び、該当枠へ進む | 固定マップとカテゴリ移動の設計は有効。押せる範囲・到着状態・フォーカスは実装検証が必要。今回クリック遷移の再試験は未実施 |
| 3 | カードを読み、横操作し、目的コンテンツへ進む | 輪郭・分類・見切れで構造は把握しやすい。長文と短文の密度差、一覧への入口、横操作の無効状態を確認する必要がある。PC先頭カードの表示を確認 |

## 3. 維持したい点

マップが導線を兼ねるため、絵の世界と情報を探す行動が分断されていない。犬タローが案内する吹き出しも、世界観の中で操作を説明できている。文字を水平にした見出し、淡色の面、黒い輪郭は、楽しさと読みやすさの共通ルールとして成立している。

カード外寸と画像余白を揃えたこと、混在するニュースにだけC2分類を置いたこと、次のカードを見せたことは維持する。マップの建物配置をPC/SPで変えない方針も、同じ場所を再び探す利用者にとって有効。

## 4. 優先度の高い改善

### R01 初訪問者にサイトの内容を一文で伝える

優先度: 高 / 分類: UX・情報設計 / 根拠: 手順1のPC画面。

ロゴ、マップ、操作方法はあるが、「えりぬい・犬タローの公式サイト」であることや、ゲーム・動画・キャラクターを楽しめることが見える文章として十分に説明されていない。既存の大きな吹き出し内に、たとえば「えりぬい・犬タローの公式サイトへようこそ。」と操作案内を階層を付けて収める。新しいラベルを増やすより、既存の案内領域を活用する。

### R02 初期表示を4pxの余裕だけで成立させない

優先度: 高 / 分類: UI・レスポンシブ / 根拠: 詳細設計の表示高計算。

ニュースの下端を表示高の4px手前に合わせる設計は、フォント差・文字拡大・改行・画像後読みで崩れやすい。モニター解像度とページの表示高も同じではない。固定値544pxだけを前提にせず、ヘッダー・ニュースの実際の必要高から案内の残り高を求める。実装候補として16〜24px程度の余裕を取り、案内の最小高を割るときは通常フローを優先する。これは提案値であり既存の確定寸法ではない。

キャラクター紹介を初期表示へ入れる必要はない。案内の大きさを主に保ち、条件が厳しいときだけ案内内の余白を調整する。

### R03 マップの押せる場所と移動先を明確にする

優先度: 高 / 分類: UX・アクセシビリティ / 根拠: 手順1の地図表示、詳細設計の透明ヒット領域。

説明で押す操作は分かるが、建物・キャラクター・装飾の全てが同じ動作かは絵だけでは判別しづらい。操作対象へポインター、ホバーとフォーカスの輪郭を付け、必要な場合はホバー時だけカテゴリ名を示す。常時表示の装飾ラベルは増やさない。

移動後は対応する見出しがヘッダーに隠れないようにし、フォーカスを移す。現在読んでいるカテゴリをマップ側で控えめに示す方式も検討できる。X・イラストは移動先が未決定のため、公開前に方針を確定する。

### R04 カルーセルに探し直せる入口を持たせる

優先度: 高 / 分類: UX・内部リンク / 根拠: 手順3の横並び表示とカード主体の構成。

カードの見切れと左右矢印は良い。一方、目的のキャラクター・記事が何枚先か分からない状態で、横操作だけを繰り返す負担がある。カテゴリに実在する一覧やチャンネル等への「すべて見る」を見出し行に設ける。既存の一覧へ結び付け、存在しない一覧ページを仮定しない。

左右ボタンは表示とクリック範囲をカード本文から離し、無効状態と件数が少ない場合を統一する。43pxという寸法だけでアクセシビリティ違反とは判定しない。スワイプ、キー操作、フォーカス位置が見えるかは別途試験する。

## 5. デザインの調整

### R05 統一カードの中で情報の密度を整える

優先度: 中 / 根拠: 手順3のPC先頭カード。

短い説明のゲームカードは下側の空白が大きく、長い動画名は本文領域の多くを使う。カード外寸は統一したまま、タイトルの使用行数、説明の最大量、日付や遷移先の位置を共通化する。短いカードを埋めるための架空の説明や不要なバッジは追加しない。

### R06 文字の強弱をサイズと余白で付ける

優先度: 中 / 根拠: 手順1・3の書体と輪郭。

既存POP書体は個性として機能しているが、見出し・操作案内・長い動画名が全て強い。書体を変えるより、見出し、カード名、本文、日付のサイズ・行高・余白の差を整理する。短いカードで読みやすいことを、長文や小さい画面の合格としない。

背景パターンは見出しやカードより弱い現在の扱いを維持する。色面と波形も機能しており、セクションごとに新しい装飾を足す必要はない。

## 6. SEOレビュー

### R07 マップをページ内移動へ変更しても内部リンクを残す

優先度: 高 / 状態: 実装条件。

マップをアンカー移動へ変えること自体をSEO上の欠点とは扱わない。ただし、これまで地図から発見できた下層ページへのリンクが消える場合は、カード・一覧・ヘッダー等へ残す。移動先のURLは通常の `a href` で持たせ、クリック処理だけに閉じ込めない。[Googleのリンク仕様](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)を参照。

### R08 カルーセルの見えないカードも取得できる構造にする

優先度: 高 / 状態: 実装条件。

画面外のカードを横へ送って表示することと、ボタンを押した後に初めて本文を生成することを区別する。重要なタイトルとリンクは、ユーザーのクリック・スワイプだけに依存せず取得できるようにする。下に置いたキャラクター紹介も同様。[Googleの遅延読込の説明](https://developers.google.com/search/docs/crawling-indexing/javascript/lazy-loading)を参照。

### R09 現行のSEO要素を新レイアウトへ引き継ぐ

優先度: 高 / 状態: 既存ソースで確認、改修後は再確認。

現行 `index.html` にはtitle、description、canonical、OGP、WebSite構造化データ、H1、セクションのH2、カードのH3がある。新Figmaで目立つ導入見出しが減ったことだけを理由に「現在H1がない」と判定しない。改修でこれらを失わず、サイト名と内容が分かる主見出し・導入文、セクション見出し、カード名の意味構造へ割り当てる。

Googleはモバイル版の内容をインデックスとランキングに使用する。SPでも主要コンテンツ・リンク・意味のある見出しを維持する。[モバイルファーストの公式説明](https://developers.google.com/search/docs/crawling-indexing/mobile/mobile-sites-mobile-first-indexing)を参照。SPの配置変更は許容されるが、PCだけに内容を残す設計は避ける。

### R10 画像とフォントを含む表示性能を測る

優先度: 中 / 状態: 未計測。

Figmaの見た目からLCP・INP・CLSや検索順位は判定できない。既存画像の適切な配信サイズ、背景タイルの再利用、表示位置に応じた画像読込、画像枠の事前確保、フォント切替後の改行を確認する。重要なファーストビュー画像を無条件に遅延読込しない。[Googleのページ体験の説明](https://developers.google.com/search/docs/appearance/page-experience)を参照。性能指標を良くすることだけで検索上位を保証するものではない。

## 7. 改修の推奨順序

1. 案内領域へサイトの紹介を加え、マップの操作対象とX・イラストの扱いを確定する。
2. 大きな案内とニュースの初期表示を保ったまま、表示高・文字拡大に対する余裕を設計する。
3. 一覧への入口、カルーセルの状態、キーボード・フォーカスを整える。
4. 共通カード内の文量と文字の強弱を整える。
5. HTMLの見出し・内部リンク・取得可能な本文・既存SEO要素を維持して実装する。
6. PC/SP実機、拡大表示、画像・データ更新後、速度指標、検索エンジンのレンダリング結果で確認する。

このレビューではFigmaのデザインノード、Webソース、公開サイトを変更していない。
