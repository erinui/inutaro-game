# TOP画面 Figma再現の実証結果

実施日: 2026-09-11
対象: 現状ローカルTOP。未コミット変更を含む。完成版ではなく事前検証。
作成先: https://www.figma.com/design/XEgScjFWiQZTUZcnbn24RO/

## 1. 結論

PC/SPの画面構造、画像、動的データ、YouTube看板の傾きをFigmaへ取り込めることを確認した。ただし自動変換のままでは書体と影が異なる。「ソースどおりの見た目」と「同書体でのテキスト編集」の両立は現状達成していない。

配置取得に自動取り込みを採用し、書体環境の対応を先行する。影については、代表リンクのイラストとCSS影を透過画像として一体化し、Figmaへ個別配置できる代替手段も実証した。フォントの制約を未解決のまま完成版を量産しない。

## 2. 実施方法

- 検証専用HTTPサーバーと独立したChrome headlessセッションを使用した。サイトのHTML/CSS/JSは書き換えていない。
- Figma公式captureスクリプトを検証サーバーのHTML応答にのみ追加し、PC/SP各1回の実取り込みを行った。
- PC: 1440 × 900、SP: 390 × 844、CSS px基準、倍率1。SPではタッチ端末の条件も有効化。
- ブラウザ側でフォント・画像の読み込みと動的カードの生成を確認した。
- `youtubePanel=0` でサムネイル、`youtubePanel=3` で登録者数表示を固定した。
- Figmaのフォント一覧、実ロード結果、レイヤー構造、書き出し画像を確認した。
- SVG直接アップロードと、実フォントから生成した文字輪郭SVGの取り込みも実行した。
- ゲーム導線だけを表示した透明背景のブラウザ画像をDPR2で撮影し、FigmaにCSS実寸270 × 270で配置した。余白40pxを含む。Figma書き出しでも影と透過を確認した。
- 検証用サーバー・ブラウザは終了済み。計画書・証跡以外のサイトソースやGitHubは変更していない。

## 3. 項目別の判定

| 項目 | 実証結果 | 判定・作成方針 |
| --- | --- | --- |
| 既存Figmaファイルへの追加 | PC/SP各フレームと素材試験3点を追加できた | 実現可能。既存成果物とは識別できる名称にする |
| PC/SPの全長取り込み | PC1440 × 5648、SP390 × 5642。ブラウザの全長と一致 | 採用。基本寸法の基準にする |
| テキストの分離 | PC123、SP120個のTEXTノードを確認 | 構造の取得は可能。書体編集とは別判定 |
| けいなんポップ体の編集 | `KeinannPOP / Black`、`KeinannPOPjp / Black`、capture由来の`KeinannPop / Regular・Bold`すべてロード失敗 | 現環境では不可。Figma側で認識・ロードできる状態にした後の再試験が必須 |
| 自動取り込みの字形 | 書き出しで本文・見出しが別書体になることを目視確認 | 自動変換のみでの完成は不可 |
| 同書体の輪郭SVG | TTFの内部名`KeinannPOP / Black`を確認。代表文字列をSVG化し、12個のVECTORとして描画成功 | 条件付きで可能。字形の代替手段だが文字入力不可。全文の折り返し・疑似太字再現は未実証 |
| 画像・外部データ | PC/SPとも画像48点の読み込み成功、失敗0。PC captureには画像塗り47ノード | 採用。背景画像等との数え方が異なるため、ノード数だけで欠落判定しない |
| マップの座標・比率 | PC402 × 639、SP334 × 530.906。説明カードはPC右、SP下 | 採用。各幅のDOM寸法に従う |
| YouTube看板の傾き | サムネイル・前面枠・背景の画像塗りと変形行列を確認。PC/SP書き出しでも斜め表示 | 取り込み可能。最終版は四隅・余白を拡大比較して微調整する |
| SVGを直接配置 | 看板SVG1000 × 1000を取り込み。2VECTORと1画像塗りを含む構造 | 採用可能。埋め込み画像を含む元素材の特性を保持する |
| マップの影 | 自動取り込みの書き出しでは路面上に大きくぼけた影が現れ、ブラウザと不一致 | 要補正。画像のアルファ形状・CSS filterとFigma effectの対応を個別調整する。忠実な補正完了は未実証 |
| 影を含めた個別透過画像 | ゲーム導線＋CSS影のPNGをFigmaに配置し、透過・影の描画を確認 | 代替手段として採用可能。各リンクを移動・拡縮できるが、絵と影は別編集不可。全リンク・SP用の最終比較は本制作で実施 |
| カルーセル末尾 | PC/SP全7ジャンルで末尾カードが表示範囲内に収まることを確認 | 状態を取得可能。各枠の実測スクロール位置を採用する |
| SPメニュー | 開閉操作と開状態の画面取得に成功 | 再現可能。Figma補足フレームへの組み立ては本制作で行う |
| 看板登録者数 | `youtubePanel=3` で「約27人」を表示・撮影できた | 状態固定可能。実証時データの値であり、最新値を意味しない |
| レスポンシブ境界 | 375/430/760/761/1280pxで検査。横スクロールの溢れなし | 基準幅と補足幅で再現可能。下表参照 |
| 装飾・ホバーのFigmaアニメーション | ブラウザアニメーションを時刻2000msで停止できた。Figmaでの連続動作再現は試していない | 静止状態の記録を採用。アニメーション実装の実現可否は今回の結果から保証しない |

## 7. 本制作に進む条件

1. Figmaで同フォントを新規テキストへロードし、文字入力・書き出しまで成功すること。未対応なら、見た目優先でアウトライン等を使う範囲と編集制限を先に確定する。
2. 自動変換で異なった影には、実証済みのリンク単位の透過画像を代替として使う。元素材SVGを別に保管し、二重の影を付けず、PC/SPそれぞれのCSS影を含めた実寸で比較する。YouTubeはサムネイルと看板の独立性を維持するため、看板の固定部分だけを対象とする。Figmaネイティブな影単体編集の完全再現と、全素材への適用は未実証。マップ全体を1枚画像にはしない。
3. 上記を満たしたPC/SPのヘッダー・マップ・カードの試作を基準に、全体を作成すること。

今回確認したのはChromeでの基準表示とFigmaでの静止画再現。Safari実機の表示完全一致、全テキストの編集可能性、全状態のFigma組み立て完了を意味しない。
