# サイトの更新と操作の信頼性 改修計画

作成日・最終更新: 2026-10-11 / 状態: 実装・統合検証済み、公開確認中

既存サイトの4課題を、表示内容と通常時のデザインを維持して改修する。実装・受け入れ条件の正本は[信頼性改善SDD](site-reliability-sdd.md)。資料整備後の利用者指示によりSDD+TDDで実装し、問題がないフェーズから順に進めた。GitHub反映も承認済み。公開設定の変更は含めない。

## 1. 対象と優先順位

| 順序 | 課題 | 現状の根拠 | 改修後 |
| --- | --- | --- | --- |
| 1 | 最新情報更新の障害波及 | 現行workflowはYouTube、note、SUZURI、コミットを順に実行。途中の失敗で後続が停止する | 取得先ごとに成否を分離し、正常取得・検証したデータだけ反映。失敗した取得先は前回のファイル群を保持 |
| 2 | ゲーム説明のキーボード操作 | あそびかたを開いてTabを押すと、閉じるボタンからダイアログ外へ移ることをChromeで再現 | 開いている間は内部でフォーカスを循環し、背面の操作を防止。閉じると元のボタンへ戻る |
| 3 | SPメニューを閉じた後の操作 | メニュー内リンクにフォーカスしてEscapeを押すと、非表示後にbodyへフォーカスが移ることをChromeで再現 | メニュー内からEscapeで閉じた場合、メニューボタンへ戻る。通常のリンク遷移は維持 |
| 4 | カード画像の読み込み失敗 | `createLatestCard` はimgを生成するがerror時の代替処理はない。既存失敗試験は寸法とリンクの保持まで | 壊れた画像表示を既存の代替表示へ切り替え、寸法・文章・リンク・スクロール位置を保持 |

基準HEADは `ecf9af55da6af3bea347648d01c09fb5b3817d74`。操作再現は2026-10-11、Chrome、390×844でのローカル確認。改修後はChrome・Safariで検証済み。VoiceOverはアクセシビリティツリーとフォーカスを確認し、音声内容の未確認を明記して公開することを利用者が承認した。

### 対象外

- 利用者指示により「動きを減らす」設定への対応を除外する。既存の設定対応も撤去せず、CSS・JSのアニメーション、smooth scroll、看板の10秒切り替えを変更しない。
- ページ追加、画面内原稿、タイトル・description、構造化データ、フォント、マップ素材・配置、カードのデザインは変更しない。
- 外部プロフィール編集・ログイン、Search Console・DNS、API新設、LINEの自動収集、画像圧縮・フォント圧縮、未追跡素材の整理は行わない。

## 3. 作業手順

1. HEAD、git status、既存の未コミット資料と利用者素材を記録する。今回の差分と他の作業を区別する。
2. 固定JSON・画像を使って変更前の通常表示と障害再現を保存する。ライブの外部データ・実APIキーをテスト条件にしない。
3. 対応フェーズのテストを先に追加する。実装不足によるRedと環境不足による失敗を区別する。
4. SDDの変更境界内だけを実装する。該当ケースをGreenにし、既存のSEO・公開・レイアウト保護試験を再実行する。
5. 使用したブラウザ、viewport、データ、件数、成功・失敗・未検証の結果を記録してフェーズの完了を判定する。
6. 最後にクリーンな公開出力を作り、作業用JSON・レポート・スクリプト・秘密情報が混入しないことを確認する。
7. [最新コンテンツ仕様](home-latest-content.md)などの「計画」記述を、実際に採用・検証した仕様と結果へ更新する。未実装のまま実装済みにしない。

## 4. 影響と対処

| 影響 | 対処 |
| --- | --- |
| 途中で書いたJSON・サムネが失敗後に公開される危険 | 取得は取得先別の作業ディレクトリへ行い、検証後に成功分だけ反映。単にcontinue-on-errorを加えない |
| 正常データを公開したが、一部取得失敗のためworkflowは失敗表示になる | 保存とpushの後に最終成否を判定。Job Summaryで更新済み・保持・スキップを区別する |
| 定期更新と手動実行が競合する | 同一更新workflowは固定concurrency groupで直列化し、実行中の処理を自動キャンセルしない |
| 実行中にmainへ別変更が入る | push競合でforce pushしない。処理を失敗として記録し、新しいmainから再実行する |
| 説明ダイアログがゲーム入力や開始処理へ影響する | 説明表示中の入力境界だけを変更。移動・ジャンプ・得点・40秒制限・音声・保存共有は保護する |
| 共通メニューの修正でPC表示やリンクが変わる | Escapeの条件とフォーカス復帰だけを変更。PCのメニュー内へTabを閉じ込めない |
| 代替画像でカード高さ・改行・横幅が変わる | 既存16:9 media枠を維持し、カード全体を作り直さない。通常・失敗の両方で2ページ目まで確認 |
| 既存ハッシュ保護が正当な変更も拒否する | 許可したコード片・参照バージョンだけを変更manifestへ登録。旧baselineを再採取しない |

## 5. 完了条件と再開方法

資料整備の完了条件は、4課題に仕様ID、変更範囲、例外時動作、TDDケース、フェーズゲートが対応し、「動きを減らす」を含む対象外項目と矛盾しないこと。実装完了・公開完了とは区別する。

残作業は公開確認。SafariのリモートオートメーションとVoiceOverは利用者の許可で一時使用し、検証後に両方OFFへ復元した。実施結果はSDDの第10節を参照。
