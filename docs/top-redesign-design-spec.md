更新日: 2026-10-20 / 版: 2.4 / 対象: エリカッテシティ TOP PC・SPと共通デザインへの適用

最新の追加承認: ニュースだけに枠付きカテゴリを残し、ゲーム一覧の補足・状態4件とキャラクター紹介の特徴14件は撤去する。見出し・名前の黄色背景、操作ボタン、ゲームHUD、通常テキストの日付・価格等は対象外。TOPカードの321×432pxは維持し、ゲーム一覧は共通の枠・影・余白のみを使って内容に応じた高さとする。具体値は[画面設計書](screen-design-specification.md)、公開／未公開と検証は[SDD第18〜21節](top-redesign-sdd.md)を参照。

ゲーム一覧カードまで公開確認済み。ラベル撤去はローカル検証済み・GitHub／本番未反映で、Figmaは更新していない。本書の更新をFigma同期や追加公開の完了とみなさない。

まちのマップをサイトの入口として扱い、ゲーム・キャラクター・動画・記事・グッズへ迷わず進めるTOPを設計する。PCは左のマップを表示したまま右の情報を読む構成、SPはマップの下に同じ情報を続ける構成とする。既存キャラクターの世界観を、配色・形状・余白・カードのまとまりで伝える。

本書はFigmaのデザイン方針と共通ルールを定める。改修要件・実装差分・工程・受入条件の入口は[TOP改修SDD](top-redesign-sdd.md)。[詳細設計書](top-redesign-detail-spec.md)には寸法、座標、状態、検証条件を記載する。2.3でWebを実装。可変画面での採用値・波形の影保護・TOP専用画像・公開状態はSDD第12〜14節を優先する。

## 2. デザインの目的

| 目的 | 設計で実現すること |
| --- | --- |
| 世界観が伝わる | 既存マップを主役にし、キャラクター素材と既存書体を一貫して使う |
| 目的の情報へ進める | マップのスポットから該当レコメンドへ移動し、カードから目的コンテンツへ進む |
| 情報を読み比べられる | カード外寸、サムネイルの扱い、タイトル・分類・日付の役割を揃える |
| 楽しさに抑揚がある | 色面の切り替え、波形境界、太い輪郭、丸い見出し、硬い影を組み合わせる |
| 編集し続けられる | TEXT、共通コンポーネント、色変数を使い、全画面を一枚画像にしない |

デザインシステム調査からは情報階層・一貫性・操作の明確さを、世界観を重視したサイト事例からは地理を使った導線・素材に由来する形や色・余白の扱いを取り入れる。事例固有のキャラクター、イラスト、装飾、アニメーションを複製しない。過去の調査内容は調査まとめ（非公開のローカル証跡: `drafts/design-research-summary-20261017/index.html`）を参照する。

## 3. 確定したデザイン判断

| 項目 | 採用方針 | ねらい |
| --- | --- | --- |
| PCの主役 | 高さに収まるマップを左側に固定 | スクロール中もまちの全体像と入口を保つ |
| PCの情報側 | 残り幅にカルーセルを縦に配置 | マップに余白を与えつつ情報を読める幅を確保 |
| SPの順序 | マップ、7つのレコメンド、フッター | PCと同じ地理・情報順で理解できる |
| マップの操作 | 対応セクションへのページ内移動 | 見たい情報を確認してからカードで遷移できる |
| カード外寸 | 全カテゴリ共通321×432pxを基準 | 一覧のリズムと操作位置を揃える |
| 分類ラベル | 混在枠のみC2、画像直下の分類欄 | サムネイル内の文字や人物を隠さない |
| カルーセル | 左右の矢印と次のカードの見切れ | 続きがあることと操作方法が伝わる |
| 見出し | 黄色の丸いラベル、傾き0度 | 楽しさと読みやすさを両立 |
| マップ枠 | 黒枠・角丸、影なし | 地図の絵を明確に見せる |
| 背景 | 淡色面と全10画像の市松パターン | サイト全体の統一とカテゴリの区切り |

セクションごとに絵文字や新しい画像アイコンを増設しない。PLAY・WATCH、単一カテゴリ枠内で繰り返すYouTube表記、「主なスポット」等の役割を持たない補足ラベルも追加しない。既存見出しの小さな丸は共通の形状装飾として扱う。キャラクターカードに犬タロー2種類の説明文を復活させない。

## 4. 画面構成と情報階層

PCは共通ヘッダーの下をマップとレコメンドの2領域に分ける。縦スクロールはページの一系統とし、マップは画面内に留まり、右の各枠とフッターへ続く。右の領域だけにポインターを置かないと読めない構造にしない。

PCのレコメンド上部は、サイト全体の見出し「エリカッテシティ」と紹介文「えりぬい・犬タローの公式サイト。」、犬タローの吹き出し案内、ニュースの順とする。サイト紹介を吹き出しの中へ混ぜず、操作説明と役割を分ける。既存犬タローの上半身表示と「マップの気になるスポットを押すと、そのエリアのおすすめへ移動できます。」の文言は維持する。2列を保つ必要幅にはカードだけでなく全6枠の見出しと一覧導線も含め、不足する画面はマップや文字を縮めず縦積みへ切り替える。

1440×900では見出し92px、案内168px、ニュース544px。ヘッダー72pxを含むニュース下端は876pxで、下端に24pxの余裕を設ける。1366×768と1280×720にも24pxの余裕を設け、カード321×432pxは縮めない。文字拡大時は実測値を優先し、初期表示への押し込みより通常フローを優先する。詳細は[レビュー対応記録](top-redesign-review-fixes-20261018.md)を参照する。

SPは共通ヘッダーの下にサイト見出し96px、マップ、レコメンドを続ける。マップは通常フローでスクロールアウトする。固定する要素はヘッダーとする。ニュース以外の6枠は見出しの下に「すべて見る」を設け、長いセクション名との干渉を避ける。2列PCでは同じ導線を見出し行の右側へ置き、幅不足による縦積み時もSPと同じ配置へ切り替える。320pxや文字拡大で見出し自体が長くなる場合はカプセルとセクションを縦に伸ばし、背景からのはみ出しや文字切れを作らない。

| 順序 | セクション | 役割 | Figmaサンプルのカード数 |
| --- | --- | --- | ---: |
| 先頭 | マップ | まちの全体像とカテゴリの入口 | — |
| 1 | ニュース | 複数カテゴリの更新を知る | 3 |
| 2 | キャラクター紹介 | 登場キャラクターを知る | 5 |
| 3 | ゲーム | 遊べるコンテンツへ進む | 1 |
| 4 | YouTube | 動画を選ぶ | 5 |
| 5 | ブログ | 記事を選ぶ | 3 |
| 6 | グッズ | 商品を選ぶ | 2 |
| 7 | LINEスタンプ | スタンプを選ぶ | 4 |
| 末尾 | フッター | 外部サービス、利用規約、プライバシーへの導線 | — |

カード数とセクション高はFigmaのサンプル状態であり、配信データの件数上限を決める値ではない。カテゴリ内の順序・最新情報の扱いは既存の取得仕様を引き継ぐ。

### 5.2 市松パターン

ユーザー提供の10画像を全て使い、1マスおきにキャラクター画像を配置する。次の行は配置マスをずらし、引いて見たときに市松状の密度になるようにする。画像を描き足したり新しい表情を生成したりしない。

2.1の採用原本は `drafts/figma-checker-pattern-20261017/checker-tile-editable.svg`。全10画像を含む960×384pxの1周期、96pxセル、中央56pxの絵をPC/SPで共通に使う。旧犬タローだけの224×224タイルとは区別する。原本SHA・10画像のID・配信出力の生成と登録は[詳細設計第6節](top-redesign-detail-spec.md)を正本とする。

原本は濃度1・透明背景とし、レコメンド側7%、マップ周辺11%を背景専用層で一度だけ適用する。色面や文字・カードを一緒に薄くしない。CSSのbackground-sizeは論理960×384px、公開用DPR2候補も表示密度を変えない。旧比較用30%を焼き込んだ画面画像は使わない。原色／淡色の比較をFigmaに保存する場合は同位置・同倍率の2レイヤーを重ね、片方だけを表示する。

制作コードには旧タイル参照があり、保存済みの最新Figma取得値はパターンの画像内容を確定する情報を含まない。したがって新レイアウト全枠が10画像版・倍率1・比較2層へ同期済みとは扱わず、G04で原本・密度・濃度を照合する。Webは淡色1層を初期状態とし、比較UIは設けない。

### 5.3 波形と装飾

隣接セクションの色面を波形で接続する。PCは右領域内、SPは画面幅内に収め、マップの絵の中に波形を重ねない。波形には操作上の意味を持たせず、独立した見出しやアイコンとして読ませない。見出しとカードには硬い影を残すが、マップ枠に影は付けない。

## 6. 書体と素材

すべての主要テキストは既存のKeinannPOPjp / Blackとし、タイトル・説明・日付・分類を編集可能なTEXTで保持する。見出しの水平、文字サイズと行間の統一で読み順を整える。別の書体へ切り替える場合や配信フォントを変更する場合は、既存の書体確認手順を適用する。

マップ、キャラクター、動画・記事・商品の画像、ロゴは既存素材を使用する。写真とイラストの元画像を保ち、共通サムネイル枠では全体を表示する。画面全体、カード全体、本文を画像化しない。キャラクター画像に新しいポーズや表情を追加しない。

マップ拡大後は必要解像度を再判定し、不足する画像だけ既存原本から配信用に再生成する。レイアウトを512px等の旧出力へ合わせて縮めず、絵の構図・透明余白・地理・操作範囲を保持する。YouTubeは見た目の看板＋画面を維持しつつ、Webでは既存の背景SVG・動画/統計・前面看板の3層を1リンクに内包する。Figmaの静的画像数をWebの要素数の制限にしない。

## 7. 共通パーツの設計

| パーツ | 構成と見せ方 |
| --- | --- |
| ブランド | 既存犬タロー画像＋編集可能なサイト名。黄色カプセルと黒枠 |
| セクション見出し | 黄色カプセル＋小さな丸＋TEXT。幅は文言に追従、回転0度 |
| Mixedカード | 共通画像枠、C2分類、タイトル、任意の説明、任意の日付 |
| Contentカード | 共通画像枠、分類分の共通余白、タイトル、任意の説明・日付。分類の重複表示なし |
| Characterカード | 共通外寸の中でキャラクター画像を大きく、名前を中央表示。説明・日付なし |
| C2分類 | 画像直下の欄に丸いカプセル。サムネイルの上に重ねない |
| カルーセル操作 | 黄色丸ボタン＋中央に左右記号。先頭・末尾では操作不能状態を区別 |

TOP内では共通外寸とカテゴリ別の画像領域の違いを区別する。Characterカードは立ち絵を見せるため画像高が262px、それ以外は158pxとする。TOPの外側のカード高は全て432px基準。下層ゲーム・プロフィールのカード高へこの値を適用しない。

## 8. 操作と動き

スポット選択で対象レコメンドの見出しまで移動する。到着時にヘッダーで見出しが隠れないようにする。PCのマップはその場に留まり、SPのマップは上へスクロールアウトする。カードの選択は従来のコンテンツページ・動画・記事・商品等への遷移を引き継ぐ。

カルーセルは自動再生せず、左右矢印または横操作で進める。横移動によってページの縦位置を変えない。全件が収まる場合は見切れを作るための複製を行わない。マップのスクロール移動とカルーセルの横移動を同じ処理にしない。

X・イラストには対応レコメンドがないため、従来の外部アカウント・イラスト一覧への直接リンクを残す。PC操作見本だけに残るイラスト→ブログ移動は採用仕様と異なるため、SDD G02の同期対象とする。他の6スポットは対応レコメンドへ移動する。ホバー時にラベル・色面・囲いを表示せず、現行Webの対象素材が上へ3px浮く動き（160ms ease）を維持する。キーボードフォーカスの輪郭は対象を隠さず表示し、行き先ラベルは出さない。

木・鳥・背景等の非操作装飾と、反応を楽しむさすけ・ぶくろちゃんを区別する。2キャラは見た目のラベルを増やさず、現行buttonの操作名・Tab/Enter/Space・見えるfocusを保持する。YouTubeの黒い下地と枠は、サムネイル・統計の切替中や画像待ちでも一体に見せる。

## 9. 編集と引き渡し

Figmaでは共通パーツ「共通パーツ / 固定マップとレコメンド」を参照する。マップは背景と「個別素材 / ゲーム」等の16画像へ分離し、画像自身へプロトタイプ反応を設定している。透明な操作用レイヤーは撤去済み。画像を動かすと操作範囲も追従する。位置変更後はPC/SPを共通座標へ同期する。カードの文言はインスタンスのTEXTプロパティ、画像は画像塗り、配色は共通変数を基本に編集する。PCとSPのカードマスターは共通、カルーセルの表示幅・切替状態は別に管理する。

Webへの移植時は固定座標を画面全体へ貼り付けず、マップの座標系と各コンポーネントの通常レイアウトを分ける。動的な件数・長文・小さい画面・画像失敗への対応は[詳細設計書](top-redesign-detail-spec.md)を用いる。

## 10. 設計状態と実装への引き渡し

FigmaのPC/SP本体、共通カード、背景色、素材分離、画像への直接反応は制作済み。過去の構造確認・YouTubeと矢印のプレビュー記録は制作時点の証跡として保持する。2026-10-18の再読ではグッズのPC/SP位置差、操作見本の文言・遷移差を確認したため、「現在の全画面が同期済み」とは扱わない。

2.2時点ではWeb未反映だったが、2.3で固定マップ構成・統一カード・SP矢印・ニュース分類・市松と波形を実装。既存の個別マップ画像、データ取得、軽量配信は再利用した。最新の採用・検証・残件は[TOP改修SDD第12〜14節](top-redesign-sdd.md)、寸法契約は[詳細設計書](top-redesign-detail-spec.md)へ集約する。

2.1の5件は資料の対応方針まで反映済み。Figmaの再取得・同期、拡大用画像とタイルの生成、全画面の切替幅検証、Web実装の完了は含めない。採否と未実施はSDD第9節へ記録した。

2.2ではグッズをPC本体基準に揃える利用者判断を記録し、W01の基準保存・保護試験を実施した。Figma連携の利用上限で現物同期は未実施。PC/SPの見た目を変更した記録ではなく、Webの新レイアウトも未実装。再開条件と試験結果はSDD第10節を参照する。
